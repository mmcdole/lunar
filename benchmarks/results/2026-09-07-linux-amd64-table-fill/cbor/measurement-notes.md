# CBOR measurement notes

Timing and retained-memory protocols are separate. The autogenerated timing
reports print a retained-delta row as 0 B because those fields are absent from
timing records. That row is unmeasured, not evidence of zero retained memory.
Use the separate retained protocol for memory conclusions.

The 15-pair scalar save timing collection includes every observation. Baseline
run 15 took 1787.385 ms; the other baseline samples were approximately
1560–1619 ms. Candidate run 1 took 1509.070 ms; the other candidate samples
were approximately 1553–1603 ms. No samples were excluded. The candidate was
faster in 10 of 15 pairs. The reported interval uses paired bootstrap sampling.

The 0.68% lower median (95% reduction interval 0.10%–1.58%) supports a modest
gain or performance close to parity. It is supporting application evidence,
not a large speedup. Descriptive reports have qualification=false because no
numeric gates were requested. The separate save qualification report enables
non-increasing median elapsed time, allocated bytes and allocation count,
with 15 clean pinned paired samples required; all those gates pass.

Separate retained measurements completed with three fresh-process pairs per
operation and one discarded warmup pair. Median heap_delta was identical:
75,721,136 B after load and 7,283,304 B after save. Median absolute heap_retained
was 75,890,752/75,890,912 B (baseline/candidate) after load and
83,174,216/83,174,056 B after save. The 160 B differences are immaterial; net
retained deltas agree. These are small memory samples, and their elapsed
figures do not replace the 15-pair timing collections. Medians are calculated
separately for each field.

Passing the individual CBOR timing gates does not qualify the implementation.
The focused Go repeat measured a significant 0.89% n-body slowdown, so the
overall no-regression condition failed. No implementation PR or published
README timing update is being promoted from this experiment.
