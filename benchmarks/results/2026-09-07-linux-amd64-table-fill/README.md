**Not qualified.** The single-pass SETLIST experiment improved binarytrees,
but the focused repeat made n-body 0.89% slower, failing the no-regression
requirement. There will be no implementation PR or promotion of these numbers
to the main README. Retained-memory checks found no material difference.
This work tracks
[issue #16](https://github.com/mmcdole/lunar/issues/16).

The clean baseline is merged main
`5fc51e449a6661340056544e995aae4fdf89dcb2`; the scalar experiment is
`73d51be1cfc1af3a1597b459511fca6b0ee68398`, labelled `scalar` in the evidence.

The experiment makes contiguous SETLIST appends reserve backing storage and
initialize each new slot with its final value while counting occupied entries.
This removes the preceding nil-initialization pass. Existing prefixes, growth policy, compaction,
integer-record fallback, and allocation accounting are preserved. The change
applies across table sizes and adds no cache or size threshold.

Lunar already implements PUC-style constructor hints and bulk SETLIST. PUC Lua
5.1.5 initializes nil with a type tag; Lunar writes a pointer. This experiment
removes duplicate writes. PUC allocates table headers and arrays separately;
there is no missing PUC coallocation technique here.

The n-body regression prevents acceptance despite the modest binarytrees gain.
It was slower in 13 of 15 pairs, including 6 of 8 baseline-first pairs and
all 7 scalar-first pairs. Its mechanism has not been isolated. Both
collections are retained in full;
no timing observations were excluded.

CBOR save exercises one-element constructors followed by growth, extending
coverage beyond binarytrees' two-element nodes. Its paired bootstrap interval
is a 0.10%–1.58% reduction; allocation counts are unchanged. All observations,
including the slow baseline sample, remain in the evidence. CBOR load uses
empty tables and dynamic insertion. Its improvement, and the lower scalar-call
and string-echo timings, are not attributed to SETLIST. See the
[CBOR notes](cbor/measurement-notes.md) for outliers and qualification policy.

Separate retained-memory checks used three pairs per operation after one
discarded paired warmup. They found no material difference:

Collection used Go 1.26.0 on an AMD Ryzen 9 9950X3D under linux/amd64 WSL2,
with `GOGC=100`, `GOMEMLIMIT=off`, `GOMAXPROCS=1`, logical CPU 2 affinity,
and `-cpu=1`. Benchmark processes were serialized. Host power, frequency, and
external host load were uncontrolled; these results describe this machine.

Fifteen rounds rotated four processes: baseline Lunar's 13 cases, scalar
Lunar's 13 cases, GopherLua's nine program/embedding cases, and go-lua's nine
program/embedding cases. This produced 660 samples across 44 rows, reusing the
scalar observations for regression and README comparisons. Each row uses a
500 ms `B.Loop` target. Setup, compilation, one warmup, and final validation are
excluded; required embedding result consumption remains timed. Go allocation
metrics describe allocation traffic.

workers and canonical input. Graph/round-trip validation and save's preparatory

load/save smoke checks passed. New tests cover backing reuse and replacement,
multiple capacities, nil holes and trimming, aliases, exact value bits, strong

review found no correctness blocker.

logs preserve the failures and repeats. No unrelated test change is included.
